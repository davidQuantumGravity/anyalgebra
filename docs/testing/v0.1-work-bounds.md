# v0.1 deterministic work bounds

This document freezes semantic work and allocation ceilings for the stable
v0.1 surface. These are reproducibility and safety contracts, not performance
claims. No wall-clock threshold is a release gate. A slower machine must
produce the same counts, frontiers, statuses, and canonical bytes.

## Stable-operation inventory

| Stable API | Growth model | Ceiling or preflight |
|---|---|---|
| `api.algebra.evaluate` | Expands the explicitly supplied sparse supports through one declared finite multilinear table | Validates arity, parents, operation ownership, and the complete coercion plan before expansion. Work is proportional to explicit input support and retained sparse constants; it performs no hidden search. |
| `api.census.spec` | Computes input-cell and raw-table counts | Carrier size is at most 256, arity at most 64, and the input table has at most 65,536 cells. Constraint, term, distinguished-element, convention-reference, and text counts have separate hard caps. No candidate is generated by the factory. |
| `api.census.enumerate` | Visits raw tables or a soundly pruned prefix tree | The reference lane selects the minimum of `max_candidates`, `max_work_units`, memory capacity, and 1,000,000 candidates before materialization. The pruning lane preflights the complete candidate count, worst-case retained bytes, and compiled constraint work before its first tree decision. |
| `api.census.canonicalize` | Enumerates allowed carrier relabelings | The exact policy computes its group order first. More than 1,000,000 permutations fails before materialization. Partition refinement has at most one pass per carrier element and changes ordering only. |
| `api.census.compare` | Computes invariants and, when needed, searches allowed relabelings | It inherits the 1,000,000-permutation hard cap. The bounded comparison route also records an explicit `max_permutations` frontier; a stopped search is inconclusive, never negative. |
| `api.census.analyze` | Runs complete finite grids or bounded exact linear work | The aggregate finite-law grid is preflighted against 20,000,000 assignments. Subsets and congruences preflight carrier size, candidate counts, closure checks, and compatibility checks before enumeration. Module-backed analysis uses `AnalysisBounds` for dimension, constraints, and elimination work. |
| `api.atlas.build` | Composes enumeration, classification, certificates, analysis, and object publication | Every corpus inherits its `CensusSpec` ceilings. The atlas schema caps corpora, representatives, links, and table cells. An incomplete enumeration cannot enter classification, and publication occurs only after the exact object set is staged and checked. |
| `api.atlas.query` | Validates an atlas object graph and filters verified representatives | Files are size-capped, schemas and versions are allow-listed, the exact link set is verified, query inputs are capped at 256 items, and no stored payload is executed. |

“Before materialization” means the relevant count or byte formula is evaluated
before constructing the candidate tuple, permutation group, pruning tree, or
partition collection that it governs. Some linear passes over already supplied
bounded data are validation, not hidden combinatorial generation.

## Frozen formulas and controls

For a carrier of size (n) and operation arity (r):

- input cells: (n^r), with the explicit nullary and empty-carrier conventions
  in the census specification;
- raw operation tables: (n^{n^r});
- reference workspace charge per retained candidate:
  (128 + 16n^r) bytes;
- full relabeling group: (n!), reduced exactly by fixed points and sort
  blocks;
- standard binary finite-law grid:
  (n^3 + 6n^2 + n) assignments;
- binary magma nuclei and commutant work:
  (3n^3) associator assignments and (n^2) commutator pairs;
- nonempty subset candidates: (2^n-1);
- congruence candidates: the Bell number (B_n), followed by an explicit
  compatibility-pair upper bound.

The order-three reference atlas has nine table cells, 19,683 raw candidates,
and a workspace charge of 272 bytes per retained candidate. Its declared
worst-case retained reference workspace is therefore 5,353,776 bytes. The
commutativity filter accepts (3^6=729) labelled tables. Classification then
retains 129 relabeling orbits and 729 member certificates. Those values are
semantic counts; the observed duration is not part of their identity.

## Preflight precedence

Reference enumeration resolves competing ceilings in canonical order and
retains the first strictly smallest capacity. Equal capacities retain the
earlier reason. The order is candidate count, work units, memory capacity, and
the implementation batch cap. Zero is a valid bound and produces an empty,
bounded prefix with next candidate index zero.

Complete pruning performs these checks before its first prefix decision:

1. declared candidate ceiling;
2. one-million-candidate implementation ceiling;
3. worst-case retained-result memory;
4. compiled constraint work over the full raw corpus.

Finite-carrier aggregate analysis runs the subobject bound gate before the
other exhaustive analyses. This matters because the default subobject domain
is intentionally much smaller than the structural `CensusSpecCore` maximum.
Declared equation grids are summed with the standard law grids and rejected
above 20,000,000 assignments before the first assignment is evaluated.

## What these tests establish

The tests freeze exact reference candidate and workspace values for empty,
singleton, unary, binary, and order-three controls. They freeze four order-two
pruning profiles, the order-two XOR analysis counts, the reference atlas
budget, group-generation rejection, and preflight-before-materialization
behavior. They deliberately avoid elapsed-time assertions.

The ceilings do not assert that the largest permitted case is fast, desirable,
or scientifically meaningful. They establish that work is finite, declared,
accounted for, and stopped at a deterministic boundary. The finite controls do
not prove a broader algebra classification or any physics claim.
