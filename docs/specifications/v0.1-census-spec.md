# AnyAlgebra v0.1 finite-algebra census contract

## Status and authority

This document is the bounded semantic contract for `V01-001`, feature
`fe.v01.finite_corpus`, API `api.census.spec`, and test
`test.v01.corpus.contract`. It refines the `NEW-01` roadmap entry without
implementing enumeration, canonicalization, isomorphism search, analysis, or
atlas persistence ahead of their assigned tasks.

The contract is normative for v0.1. Later changes require an explicit versioned
contract change and corresponding tests. Examples below define small control
domains; they are not claims about all finite algebras.

The opening baseline audit is the committed
`tests/fixtures/legacy/v0.1-baseline-audit.json`. It is a portable historical
receipt of the external working-copy drift in `AlgMul.wl`, the two changed line
locations, and the resulting fail-closed legacy-test baseline. It intentionally
contains no machine-specific paths and does not require the research checkout.

## Scope

v0.1 specifies reproducible censuses of one finite, total operation on one
finite carrier. The operation may have arbitrary finite arity within declared
resource bounds. A census may impose allow-listed algebraic constraints and may
classify tables under either literal equality or a declared carrier-relabeling
policy.

In scope:

- canonical finite carriers labeled `0, ..., n-1`;
- one total operation of declared arity;
- immutable, safe, content-addressed census specifications;
- allow-listed constraints with canonical parameters;
- literal or carrier-relabeling equivalence;
- deterministic candidate, input-tuple, and permutation orders;
- deterministic work ceilings checked before generation;
- source and convention references by stable identifiers;
- complete, bounded-incomplete, unsatisfiable, invalid, and failed outcomes.

Partial operations, multiple operations, relations, many-sorted carriers, and
linear structure constants remain valid AnyAlgebra structures, but their census
enumeration is outside this v0.1 contract.

## Definitions

### Finite carrier

A finite carrier of size `n` is the ordered tuple `(0, ..., n-1)`, where `n` is
an exact nonnegative integer. The integer labels are serialization labels, not
extra mathematical structure. A different labeling belongs to the same orbit
only when the selected equivalence policy permits that relabeling.

### Operation table

For carrier `X` and operation arity `r`, a total operation table represents a
function `X^r -> X`. Input tuples are ordered lexicographically. Table outputs
are stored in that input order. Before constraints, a nonempty carrier has
`n^(n^r)` candidate tables.

For `n = 0` and `r > 0`, there is one empty total function. For `n = 0` and
`r = 0`, no output element exists, so the corpus is `Unsatisfiable`. These
conventions must be tested rather than inferred from programming-language empty
products.

### Constraint

A constraint is an allow-listed identifier plus a canonical, schema-validated
parameter record. Examples include `associative`, `commutative`, `idempotent`,
`has_two_sided_unit`, and exact cell assignments. Serialized callables, import
paths, closures, and executable predicates are prohibited.

### Equivalence policy

`literal` treats two tables as equivalent only when their canonical table bytes
are equal. `carrier_relabeling` permits bijections of the carrier that preserve
every operation cell and all declared distinguished elements. The policy is
part of the specification and therefore part of its semantic hash.

### Census

A census is the execution of one accepted specification by one declared
algorithm version. A census result includes expected and evaluated candidate
counts, accepted and rejected counts, skip reasons, deterministic work counts,
the outcome tag, and hashes of its specification and artifacts.

## Finite-carrier versus finite-basis structures

A finite carrier has finitely many elements and can support exhaustive table
enumeration. A finite-basis algebra such as `H`, `Hs`, `O`, or `Os` has a finite
basis over an infinite coefficient domain such as `QQ` and therefore usually
has infinitely many elements.

Consequently, finite-basis controls are not members of a finite-carrier census.
They may test generic evaluation, identities, basis transport, and analysis,
but their successful basis-level checks do not constitute a carrier census or
an unqualified proof over arbitrary coefficients.

## Census specification axes

The planned constructor is:

```python
CensusSpec.create(
    *,
    carrier_size,
    arity,
    constraints,
    equivalence,
    ordering,
    bounds,
    convention_refs=(),
)
```

An accepted specification records every axis below.

| Axis | Required contract |
|---|---|
| carrier size | Exact nonnegative integer and canonical carrier labels |
| operation arity | Exact nonnegative integer within the declared arity ceiling |
| constraints | Ordered canonical records using only registered identifiers and bounded parameters |
| equivalence policy | Exact policy identifier and any distinguished elements it must fix |
| ordering | Candidate-table, input-tuple, constraint, and permutation orders |
| resource bounds | Deterministic candidate and work ceilings, plus separately labeled operational ceilings |
| convention references | Immutable source or convention IDs, sorted where order has no semantics |

The full record also contains a schema tag, schema version, algorithm contract
version, and semantic hash. Creation snapshots each iterable at most once,
rejects duplicate unordered declarations, and validates bounds before consuming
a user candidate iterable or generating a table.

## Outcomes and evidence

- `Complete`: every candidate in the declared bounded corpus was accounted for,
  all required cross-checks passed, and expected and observed counts agree.
- `BoundedIncomplete`: a declared deterministic ceiling stopped work. The result
  reports the exact frontier and never uses the words complete or exhaustive.
- `Unsatisfiable`: the accepted constraints or carrier/arity combination admit
  no operation, with a checked reason or exhaustive zero count.
- `InvalidSpec`: construction failed before enumeration, with a stable field and
  reason that do not render unsafe caller objects.
- `Failed`: execution failed after accepting the specification. Completed work,
  the smallest reproducible failure, and artifact status remain explicit.

Package execution status, mathematical outcome, corpus completeness, and
scientific interpretation are separate fields. A successful run cannot promote
its own evidence tier. Fingerprint equality is not proof of isomorphism;
positive isomorphism claims require a checked operation-preserving bijection.

## Determinism and resource bounds

The reference order is:

1. input tuples in lexicographic carrier order;
2. output vectors as base-`n` digits in lexicographic order;
3. constraints in canonical identifier/parameter order;
4. carrier permutations in lexicographic image order;
5. results by canonical table bytes and then canonical identifier.

Semantic work ceilings use deterministic counts such as generated candidates,
constraint evaluations, relabelings, and table-cell comparisons. Wall time and
memory may stop an operational run, but they cannot by themselves support a
reproducible completeness claim. A bound is checked before the unit of work it
would exceed.

Canonical serialization is UTF-8 JSON with registered tags, explicit integer
schema versions, sorted object keys, semantic sequence order, and no executable
payloads. Hashes cover canonical bytes. Interrupted or partial artifacts cannot
be opened as complete atlases.

## Control examples

### Singleton binary carrier

For `n = 1`, `r = 2`, and no constraints, exactly one table exists. Its sole
cell is `0 * 0 = 0`. Literal and carrier-relabeling equivalence coincide.

### Two-element binary carrier

For `n = 2`, `r = 2`, and no constraints, there are `2^(2^2) = 16` literal
tables. Commutativity leaves three independent cells and therefore eight
literal tables. Idempotence fixes both diagonal cells and leaves four literal
tables. These are hand-checkable reference-enumerator controls, not the final
largest v0.1 corpus.

### Empty carrier boundaries

For `n = 0`, `r = 1`, there is one empty total operation. For `n = 0`, `r = 0`,
the result is `Unsatisfiable` because a nullary operation must choose an output.

### Finite-basis exclusion control

The quaternion and octonion fixtures have finite bases but infinitely many
elements over `QQ`. They are composition controls in later v0.1 tasks and are
not counted among the finite-carrier tables above.

## Explicit non-goals

- No unbounded enumeration or claim about all finite nonassociative algebras.
- No fingerprint equality as proof of isomorphism.
- No silent use of hash order, object identity, wall time, or backend iteration
  order as mathematical ordering.
- No serialized arbitrary callable, import path, or executable constraint.
- No stable named quaternion, octonion, Lie, Clifford, Jordan, or exceptional
  hierarchy in this task.
- No tensor-Jordan, octo-octonionic E8, manifold, gauge-gravity, or brane API.
- No use of AlgMul or experimental exceptional code as a correctness oracle.
- No modification or silent re-pinning of external legacy evidence to make a
  required test pass.
